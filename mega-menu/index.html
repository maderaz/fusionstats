Build guide

What to do

  1. Read mega-menu.html top to bottom. It has three parts: the CSS variables (--mm-*) at the top of the style, where all rebranding happens; the MENU config at the top of the script, the only part that holds content; and the rendering and behaviour below it, which should not need edits to add options.
  2. Port it into the target project as-is first (same markup, class names and behaviour), then map the --mm-* variables to the project's design tokens. Do not rewrite the interaction logic.
  3. Replace the MENU content with the project's real menus.

The config

const MENU = {
  brand: { name: 'Fusion', href: '/' },
  menus: [
    {
      label: 'Products',      // the top-bar item
      columns: 2,             // 1, 2 or 3 columns of links in the bubble
      right: false,           // true for items near the right edge: opens leftwards
      feature: {              // optional dark card in its own column at the right
        kicker: 'Fusion today', value: '$81.0M', text: 'One or two lines.',
        cta: 'Open stats', href: '/stats',
      },
      links: [                // either links...
        { title: 'Vault Factory', desc: 'One line, short', href: '/factory',
          tag: 'NEW',         // optional small pill after the title
          icon: 'M2.5 15.5h13M4 15.5V8...' },  // SVG path data, 18 x 18 grid, stroked
      ],
      // ...or groups, each with a small heading:
      // groups: [{ name: 'Build', links: [...] }, { name: 'Trust', links: [...] }],
    },
  ],
  ctas: [
    { label: 'Talk to Us', href: '/contact', style: 'ghost' },  // hidden on phones, repeated in the sheet
    { label: 'Launch App', href: '/app', style: 'solid' },      // stays in the bar on phones
  ],
};

Icons are outlines (stroke 1.5, round caps) on an 18 × 18 grid: any 18 × 18 line icon's path data works. External links (http…) open in a new tab.

Behaviour, which must be kept

  • Desktop: a panel opens on hover. Its 14px top padding is an invisible bridge between the bar and the panel, so the pointer can move down into it without it closing.
  • Click or Enter on an item toggles its panel; one is open at a time.
  • Escape, or a click outside the bar, closes everything; leaving an item with the pointer closes it.
  • Keyboard: :focus-within keeps a panel open while Tab moves through its links; buttons carry aria-expanded and aria-controls.
  • Phones (below 980px): the items fold into a sheet under the bar, each menu a <details> fold. Change the breakpoint in both --mm-collapse and the @media (max-width: 980px) rule.
  • Reduced motion: transitions switch off under prefers-reduced-motion.

Design rules

  • Titles and labels stay on one line; descriptions may wrap to two (keep them near 40 characters).
  • Gaps: 12px icon to text, 6px between links, 10px panel padding, 8px label to chevron.
  • The feature card is optional and 230px wide: one figure or one highlight, not a list.
  • More than about 8 links: use groups and 2 or 3 columns.

Checklist

  • Each panel opens on hover, click and Enter, and closes on Escape and an outside click.
  • Moving the pointer from an item down into its panel does not close it.
  • Items near the right edge use right: true, so their panel stays on screen.
  • Below the breakpoint the sheet opens, folds work, and nothing scrolls sideways.
  • No label wraps at 320, 768, 1024 or 1440px; all links point at real pages.
