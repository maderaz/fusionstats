Hub and spoke

Liquidity lives in Hubs; users act on Spokes, each with its own risk parameters, oracle and reserve list. A Spoke reserve is an append-only reserveId pointing to one asset of one Hub, so the same underlying can be listed more than once on a single Spoke.

HubsCore, Prime, Plus, Global Dollar
SpokesMain, Bluechip, Ethena Correlated, Forex, Gold, and more
FusionThe Plasma Vault acts on Spokes through the fuses

Supplying does not enable collateral. Only reserves flagged with setUsingAsCollateral count towards the health factor; without it every borrow reverts with HealthFactorBelowThreshold. Hence a fuse of its own for collateral.

There is no E-Mode. Risk is segmented by choosing the Spoke, so one market, ID 49, covers every Spoke.

The Bluechip Spoke, for one, lists USDC twice: as reserve 4 on the Prime hub and reserve 7 on the Core hub, with different rates and caps.

All run by delegatecall from PlasmaVault.execute, each with enterTransient and exitTransient variants for batched flows.

Permissions

Each grant is one bytes32 substrate: a Spoke, a reserve and two flags. Any grant allows supply, withdraw, repay and disabling collateral; isCollateral adds enabling collateral; canBorrow adds borrowing.

BitsFieldContents
255..248Type flag8 bits; 1 = Reserve
247..88Spoke160 bits; the Spoke's address
87..56Reserve ID32 bits
55..48Flagsbit 0 isCollateral, bit 1 canBorrow
47..0ReservedMust be zero

getReserveGrant probes the four flag variants of a (spoke, reserveId) pair and returns their union, so the order of granted substrates never matters. Atomists are expected to grant one variant per reserve.

Build a substrate

Enter a Spoke, a reserve and the flags to see the word to grant and what it allows.

    Validation

    Supply, withdrawAny grant for (spoke, reserveId)
    Instant withdrawA grant, no granted variant with isCollateral, and not collateral on the Spoke now
    BorrowA grant with canBorrow
    RepayAny grant, even after canBorrow is revoked
    Enable collateralA grant with isCollateral
    Disable collateralAny grant; the Spoke enforces the health factor

    Supply fuse

    AaveV4SupplyFuse

    • enter checks the grant, cross-checks the reserve's underlying, caps the amount at the vault's balance, supplies, then enforces minShares.
    • exit withdraws with any grant.
    • instantWithdraw serves user redemptions: only for reserves never granted as collateral and not collateral on-chain, catching a failing Spoke so one reserve cannot block every withdrawal.
    AaveV4SupplyFuse.sol · enterL140
    if (!AaveV4SubstrateLib.canSupply(MARKET_ID, data_.spoke, data_.reserveId)) {
    revert AaveV4SupplyFuseUnsupportedSubstrate("enter", data_.spoke, data_.reserveId);
}
_validateReserveAsset(IAaveV4Spoke(data_.spoke), data_.reserveId, data_.asset);

uint256 finalAmount = IporMath.min(ERC20(data_.asset).balanceOf(address(this)), data_.amount);
ERC20(data_.asset).forceApprove(data_.spoke, finalAmount);

(uint256 shares, ) = IAaveV4Spoke(data_.spoke).supply(data_.reserveId, finalAmount, address(this));
if (shares < data_.minShares) {
    revert AaveV4SupplyFuseInsufficientShares(shares, data_.minShares);
}

    Borrow fuse

    AaveV4BorrowFuse

    • enter borrows only with canBorrow; the Spoke reverts HealthFactorBelowThreshold if no collateral is enabled.
    • exit repays with any grant, so debt can always be repaid even after canBorrow is revoked.
    • The repay is capped at the vault's balance; the Spoke caps it at the total debt.
    AaveV4BorrowFuse.sol · exitL188
    if (!AaveV4SubstrateLib.canSupply(MARKET_ID, data_.spoke, data_.reserveId)) {
    revert AaveV4BorrowFuseUnsupportedSubstrate("exit", data_.spoke, data_.reserveId);
}
_validateReserveAsset(IAaveV4Spoke(data_.spoke), data_.reserveId, data_.asset);

uint256 balance = ERC20(data_.asset).balanceOf(address(this));
uint256 repayAmount = IporMath.min(balance, data_.amount);
ERC20(data_.asset).forceApprove(data_.spoke, repayAmount);

(uint256 sharesRepaid, uint256 repaid) = IAaveV4Spoke(data_.spoke).repay(
    data_.reserveId, repayAmount, address(this)
);

    Collateral fuse

    AaveV4CollateralFuse

    • enter enables a reserve as collateral, only with a grant carrying isCollateral.
    • exit disables it with any grant; the Spoke enforces the health factor.
    • Needed because supplying alone never enables collateral on Aave V4.

    Balance fuse

    AaveV4BalanceFuse

    • Walks the granted reserve substrates, counting each (spoke, reserveId) pair once.
    • Sums (supplied − total debt) × price per reserve through PriceOracleMiddleware, in WAD.
    • Debt is always read, whatever canBorrow says, so revoking a borrow permission never hides debt. Reverts if debt exceeds supply.
    AaveV4BalanceFuse.sol · balanceOfL61
    bytes32[] memory substrates = PlasmaVaultConfigLib.getMarketSubstrates(MARKET_ID);
for (uint256 i; i < len; ++i) {
    if (!AaveV4SubstrateLib.isReserveSubstrate(substrates[i])) continue;
    substrate = AaveV4SubstrateLib.decode(substrates[i]);
    if (_isDuplicate(substrates, i, substrate.spoke, substrate.reserveId)) continue;
    balanceTemp += _calculateReserveBalance(
        IAaveV4Spoke(substrate.spoke), substrate.reserveId,
        plasmaVault, priceOracleMiddleware
    );
}

    A typical flow

    Three fuse actions in one PlasmaVault.execute, the README's own example on the Bluechip Spoke:

    1. Supply 10 WETH into reserve 0 of the Bluechip Spoke (AaveV4SupplyFuse).
    2. Enable collateral on the same reserve 0, so it counts towards the health factor (AaveV4CollateralFuse).
    3. Borrow 10,000 USDC from reserve 4, Bluechip's USDC on the Prime hub (AaveV4BorrowFuse).
    README.md · exampleL159
    FuseAction[] memory actions = new FuseAction[](3);
actions[0] = FuseAction(supplyFuse, abi.encodeWithSignature("enter((address,address,uint256,uint256,uint256))",
    AaveV4SupplyFuseEnterData({spoke: BLUECHIP_SPOKE, asset: WETH, reserveId: 0, amount: 10e18, minShares: 0})));
actions[1] = FuseAction(collateralFuse, abi.encodeWithSignature("enter((address,uint256))",
    AaveV4CollateralFuseEnterData({spoke: BLUECHIP_SPOKE, reserveId: 0})));
actions[2] = FuseAction(borrowFuse, abi.encodeWithSignature("enter((address,address,uint256,uint256,uint256))",
    AaveV4BorrowFuseEnterData({spoke: BLUECHIP_SPOKE, asset: USDC, reserveId: 4, amount: 10_000e6, minShares: 0})));
PlasmaVault(vault).execute(actions);

    Grants and open positions

    The fuses deliberately do not tie a grant change to existing positions, and grantMarketSubstrates always replaces the whole set. The atomist keeps these rules.

    SituationEffectRule
    A reserve with debt loses its grantDebt drops out of the balance: NAV overstated, share price inflatedNever revoke a reserve the vault borrows; repay first
    A reserve with supply loses its grantSupply drops out of NAV and cannot be withdrawn until re-grantedWithdraw first, or re-grant to recover
    Collateral re-granted without isCollateralStays enabled on the Spoke; enabling again is refused, disabling worksDisable collateral before downgrading the grant
    Debt re-granted without canBorrowNew borrows refused, repay works, debt still countedThe intended way to wind a position down
    Reserve granted before Aave lists itIgnored by the balance fuse; supply and borrow revert ReserveNotListedHarmless: active once listed

    Only the last row is tolerated in code; the others are documented risks, not enforced invariants.

    Security

    • No position manager, ever. The vault acts for itself on the Spoke (onBehalfOf == msg.sender).
    • Instant withdraw is double-guarded. Limited to non-collateral reserves by grant flag and by live on-chain status, so user withdrawals can never degrade a leveraged position.
    • Exact approvals. Only granted Spokes are called; supply and repay pull exactly the approved amount (SafeERC20.forceApprove).
    • Aave's own limits stand. Paused and frozen flags and Hub caps are enforced by Aave; the fuses do not pre-check them.
